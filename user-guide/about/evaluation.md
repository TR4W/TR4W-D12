# Evaluate the prototype

This experiment tests whether a small, edited operator guide is useful before committing to a full manual migration.

## Try these tasks

1. Find the instructions appropriate to your installed version.
2. Find how to reopen an existing contest.
3. Switch between serial and network radio instructions.
4. Search for `WSJT-X BROADCAST PORT` and follow the result to the setup procedure.
5. Switch to dark mode and review a table on a narrow screen.
6. Open the built site locally with the network disconnected and check search and navigation.
7. Find how to set a backup interval and identify the manual backup key.
8. Find how to log two worked parks and check the resulting ADIF fields.
9. Find the distinction between TR4W's name and the availability of a particular native build.

Record whether each task succeeds without help, where you hesitate, and any label that differs from the actual program. These are evaluation tasks, not claimed test results.

## What Material contributes

The prototype uses navigation sections, browser-side search, light/dark themes, tabbed procedures, expandable evidence notes, and offline support. Fonts use the local system stack. No custom theme or external JavaScript service is required.

## What still requires editorial work

MkDocs turns reviewed Markdown into a navigable site. It does not resolve conflicting manuals or determine whether a feature works. The main ongoing effort will be verifying procedures and maintaining their relationship to releases.

## Suggested next slice

Complete one first-QSO walkthrough with screenshots, then run the drafted backup/export, POTA, and keyboard procedures with an operator on the target platform. Follow with CW setup and a tested migration/recovery walkthrough. A generated settings index could follow once defaults, scope, and help text have a reliable extraction contract.

The prototype is local only. Publishing to GitHub Pages or the project website can follow a content review; no deployment workflow is enabled here.
